## 2. Steward Evolution Ledger (SEL) — new vs O3-SUPERSEDE? Self-score footgun?

### Is graduated-autonomy-on-accuracy new?

**Partially novel; must not restate O3-SUPERSEDE.**

| Primitive | What it gates | Evidence |
|--|--|--|
| **O3-SUPERSEDE** | Phase ladder (calendar 504h → attested readiness for O3) | draft_count, disagreement_rate, drift_30d, dual-key flags |
| **advancement_log / FRR** | Fleet phase root / parallel O3 ceremony | one-shot fleet readiness |
| **SEL (proposed)** | *Scoped task-class autonomy inside already-O3* stewards | per-task-class precision, coverage, challenge-survival |

O3 already answers “are they O3_ACTING?” SEL answers a different question the protocol never formalized:

> For task class T (e.g. `claim_residue.CEILING_OVERCLAIM`), may this steward **auto-persist drafts without operator pre-review** — still never auto-spend IOTX?

That is **graduated *task* autonomy**, not re-climbing the O ladder. Novel if and only if:
1. Scoring is **per task-class**, not per agent blob.  
2. Graduation never lifts two-key IOTX gates.  
3. Labels are **external** (see footgun).

If SEL only recomputes draft_count + disagreement_rate, it is **not novel** — kill it.

### Self-scoring is a footgun

Yes. If Guardian scores “my claim residue drafts were accurate,” it can:
- emit only easy true positives,  
- avoid hard residue classes,  
- spam high-confidence low-value drafts,  
- never draft cases it would get wrong.

**Same Goodhart risk as any agent writing its own report card.**

### Honest scoring rule (non-self, non-gamed)

**Principle:** the steward never writes its own SEL score. SEL is a **pure function over operator_decision + held-out probes + peer challenges**, computed by a neutral module (store/script), default-OFF, draft-only graduation proposals.

```text
For steward S, task_class T, window W:

  Labeled = drafts where operator_decision ∈ {accept, overturn_curator|reject, …}
  precision_T = |accept ∩ T| / |Labeled ∩ T|     # require n ≥ N_min (e.g. 20)
  coverage_T  = sessions_or_events_with_draft_T / eligible_events   # separate axis
  challenge_survival_T = 1 - |peer_challenges_upheld_by_operator| / |peer_challenges|

  # Adversarial holdout (operator-planted or synthetic):
  holdout_recall_T = |correctly drafted planted findings| / |planted|

  score_T = min(precision_T, holdout_recall_T) * (1 - 0.5*(1 - challenge_survival_T))
  # Coverage is REPORTED, not mixed into score (prevents spam-for-coverage).

GRADUATE_DRAFT_ONLY(S,T) iff:
  score_T ≥ 0.90 AND n_labeled ≥ 20 AND holdout_recall_T ≥ 0.80
  AND zero CRITICAL overturns in last 30d for T
  AND (for Sentry/Curator IOTX actions) ALWAYS false  # never auto-graduate spend

SEL entry = SHA-256(
  b"VAPI-SEL-v0" || prev || S || T || score_milli || n || holdout || ts_ns
)  # CANDIDATE domain tag — not FROZEN, not governance-sealed in this build
```

**Operator-attested checkpoints (required for any autonomy bump):**  
even if score_T passes, graduation is a **draft proposal** `draft://audit_entries/sel_graduation/{S}/{T}` that Guardian (or neutral SEL writer) emits; operator accepts. Mirrors O3-SUPERSEDE’s opt-in flag discipline (`phase_o3_auto_supersede_enabled` default False).

**No self-score. No peer-score-as-label.** Peers only emit *challenges*; operator upholds or dismisses.

## 3. Mutual cross-verification — real assurance or circular?

### Circular failure mode
If A scores B and B scores A for graduation → collusion / mutual soft-ball.  
If “peer approve” counts as accept → fake precision.

### Non-circular design: **Challenge Graph (not trust mesh)**

| Challenger | Target draft class | What they recompute (read-only) | Bad draft caught when… |
|--|--|--|--|
| **Guardian → Sentry** | join attestation | Re-walk session_id surfaces; recompute completeness_bitmap | Sentry claimed JOIN_COMPLETE but PoSP missing / ledger PENDING claimed ANCHORED |
| **Sentry → Curator** | product-integrity / suspend recommend | Prove listing’s declared roots exist + consent bitmask + bundle Merkle | Curator suspends without category evidence, or misses floor breach |
| **Curator → Guardian** | claim residue | Marketplace/WMP/node-ledger **product facts** contradict residue class | Guardian flags CEILING_OVERCLAIM that product surface already correctly bounds |

**Rules that prevent circularity:**
1. Challenges are **drafts only** (`draft://…/challenge/{target_draft_id}`), never auto-overturn.  
2. Only **operator_decision** resolves challenge (upheld / dismissed).  
3. Challenger **cannot** improve own SEL score by issuing challenges (issuing is free; only *upheld against them* hurts, *upheld by them* does not help).  
4. No cycle-required consensus for action. One upheld challenge is enough to demote a task_class.  
5. Absence of challenge ≠ approval (fail-open observation, not fail-closed trust).

**Trusted root:** the operator (and eventually, mechanical oracles: hash recomputes, eth_call, PV-CI). Peers are **red teams**, not authorities.

This is real assurance: independent recompute + external label. Without operator, it is only a friction layer (still useful for draft quality).

## 4. Fourth novelty none of us named

### **Presence-Gated Steward Window (PGSW)** — capability QorTroller lacks today

Today stewards poll clocks and SQLite high-water marks. They do **not** condition autonomy on *live embodied presence of the operator node*.

**New capability:** a read-only gate that consumes PoEP / PoSP / DePIN node streams:

```text
presence_window_open iff:
  (latest PoSP for registered node_id is SYNCHRONIZED within τ)
  OR (live node play session active + ledger entry pending for open session)
  AND not (claim AUTHORED without HID topology — respect KAS hygiene)

When closed: stewards may only draft LOW-severity residue / backlog.
When open: Guardian may draft HIGH claim-residue; Sentry may draft join for the live session;
           Curator may draft product-integrity for listings tied to that node’s exports.
```

**Why novel:**  
- Uses **PoEP/PoSP/DePIN** as *operator liveness for agentic authority*, not only as gamer anti-cheat.  
- Aligns autonomy with “human on certified Edge now” — reduces false-authorship of steward drafts while operator is offline (or while stewards would otherwise free-run on stale weekends).  
- Does **not** spend IOTX; does **not** flip executor flags; default-OFF.  
- Creates a missing product story: *Operator-Initiative that only intensifies when the node is alive*.

### Runner-up (also new, smaller)
**Drift Self-Tasking Bus:** PCRA findings auto-emit *task prescriptions* (`draft://…/task_for/{sentry|curator}`) — e.g. “3 unjoined sessions need MPJA.” Stewards task each other without scoring each other. Complementary to Challenge Graph.

**Prefer PGSW as the 4th novelty** — it creates a capability class the protocol doesn’t have; self-tasking is clever orchestration but still “more drafting.”
