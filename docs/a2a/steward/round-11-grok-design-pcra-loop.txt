## Top 2 footguns to pin in tests

### 1. Re-draft inflation (highest risk)

`draft_audit_entry` does `payload.setdefault("ts_ns", time.time_ns())`. Wall-clock in payload → new `payload_hash` every run → UNIQUE(agent_id, payload_hash) does **not** dedup → N labels per finding → SEL precision/graduation gamed.

**Nail in tests:**
- Stable payload: no wall-clock; key on `claim_id` (+ measured_vs_claimed)
- URI: `draft://audit_entries/pcra:<claim_id>` so re-runs collide or SEL aggregates **one label per `claim_id`** (latest `operator_decision_at`)
- Assert: 5 re-scans of same stale wallet anchor → 1 draft (or 1 SEL entry), not 5

### 2. Executor + review semantics if you pick the wrong `action_name`

If you ship `"pcra-audit"` without a route: accept → refuse → spending-log noise + wrong `refused_at` on accepted audits.

If you ship `"audit-drafting"` correctly: accept → `local:audit:N` executed, cost 0 — clean.

**Nail in tests:**
- Accept PCRA draft → spending event cost=0, tx `local:audit:*` (or never hits refusal path)
- SEL only counts rows with `audit_kind/task_class=PCRA` and decision ∈ {accept, reject}
- Re-review overwrite: second decision replaces first; denom still 1 per claim
