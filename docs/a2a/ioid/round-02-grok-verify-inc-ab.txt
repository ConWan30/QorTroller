## Findings first

### F1 — BLOCKING (Inc-B): content-hash assembly truncates one byte

`compute_did_content_hash` is correct and **byte-equal** to `AgentRegistrar.compute_did_content_hash` (canonical JSON → keccak).

The only call site corrupts it:

```447:447:bridge/vapi_bridge/controller_ioid_registration.py
        did_hash=bytes.fromhex(did_hash[2:]),
```

`Web3.keccak(...).hex()` returns **64 hex chars with no `0x`**. `[2:]` drops the first byte → 31-byte “hash”. Proven:

| | |
|--|--|
| true | `cfc99a07…` (32 B) |
| after `[2:]` | `c99a0737…` (31 B) |

Tests pass because they only unit-test the pure function, not the dry-run assembly path. Inc-D would ship a wrong on-chain `hash` if this stays.

**Fix (minimal):**

```python
_raw = did_hash.removeprefix("0x") if isinstance(did_hash, str) else did_hash.hex()
did_hash=bytes.fromhex(_raw.removeprefix("0x") if False else (did_hash[2:] if did_hash.startswith("0x") else did_hash)),
```

Cleaner: make `compute_did_content_hash` return `bytes` like agents, or:

```python
did_hash=bytes.fromhex(did_hash.removeprefix("0x")),
```

Add an integration test: dry-run (or a thin helper) asserts assembled `hash` == full 32-byte doc keccak.
