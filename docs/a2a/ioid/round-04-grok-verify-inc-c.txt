## Findings first

### F1 — **BLOCKING**: mint can exit “success” with `CONTROLLER_TOKEN_ID=None`

`scripts/operator_session_register_controller.py:270-277`

After a status=1 mint, balance delta is checked, but log-parse failure is **not** fatal:

```270:277:scripts/operator_session_register_controller.py
    token_id = _minted_token_id_from_logs(w3, rcpt, nft, gamer)
    bal_after = nft_c.functions.balanceOf(gamer).call()
    ...
    if bal_after != bal_before + 1:
        ... sys.exit(1)
    print(f"  CONTROLLER_TOKEN_ID={token_id}")
```

`register-project` has an enumeration fallback (`tokenOfOwnerByIndex`); **mint does not**. Operator can spend gas, see balance+1, and copy `CONTROLLER_TOKEN_ID=None` into Inc-D. Same class as Inc-B: green unit tests, silent production-path hole.

**Minimal fix:** if `token_id is None` after mint → fall back to enumerable (add `tokenOfOwnerByIndex` / `totalSupply` to least-privilege ABI) **or** `sys.exit(1)` with explorer link. Never print `None` as the exit artifact.

### F2 — **BLOCKING**: Transfer-log parser can `IndexError` after a paid tx

`scripts/operator_session_register_controller.py:151-170`

```python
to_addr = "0x" + str(topics[2])...   # assumes len(topics) >= 3
return int(str(topics[3])...)         # assumes len(topics) >= 4
```

No `len(topics) >= 4` guard. An ERC-20-shaped Transfer (3 topics) on a receipt log matching address+topic0, or any truncated topic list, crashes **after** broadcast — spend done, no clean readback.

Also does **not** require `from == 0x0` (mint/project mint). Agent step_3 uses `process_receipt` event decode instead of raw topics.

**Minimal fix:**

```python
if len(topics) < 4:
    continue
# mint/register only:
from_addr = str(topics[1]).replace("0x", "")[-40:]
if int(from_addr, 16) != 0:
    continue
```

Prefer extracting to `controller_ceremony.minted_token_id_from_logs(...)` + synthetic-log unit tests (Inc-B lesson: pure path tested, load-bearing path not).
