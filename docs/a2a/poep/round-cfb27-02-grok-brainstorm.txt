## D. Adversarial on S3 (snap-reaction liveness)

### How you game it (or how humans look like cheats)

1. **Legitimate anticipation (the load-bearing confound)**  
   Hard counts, film study, motion tells, audible cadence — humans *should* move before the ball is snapped. Sub-80 ms "reactions" can be true positive humans. Absolute lower band alone = false bot rate on good defenders.

2. **Cadence / AI snap prediction**  
   Model pre-snap clock + formation → fire input at predicted snap. With OCR lag, a script can sit inside 80–280 ms by design ("band camping").

3. **Offense asymmetry**  
   On offense the snapper *generates* the stimulus. Measuring "reaction to own snap" is nonsense (or measures motor plan, not liveness). S3 without possession/side filter is garbage.

4. **OCR lag as free pad**  
   If t_stimulus = OCR detect time (not true on-screen snap), measured latency = true_latency − ocr_lag. Scripts can look human; humans can look slow/bot-high.

5. **Pre-snap feathering**  
   Micro-inputs already held; "reaction" is release/edge on an armed control — looks instant.

6. **Haptic-free script with humanized jitter**  
   Gaussian 120±30 ms on every snap defeats naive band checks; needs **distribution** forensics (CV, multimodality), not single-shot thresholds.

### Rails that keep it honest

| Rail | Rule |
|---|---|
| **Candidate forever (v0)** | Tag `QORTROLLER-SNAP-REFLEX-v0 CANDIDATE`. Never BLOCK/CERTIFY/eligibility. Never humanity_probability weight. |
| **Defense-only / non-snapper** | Only score when local player is *not* the snap initiator. Without side detection: require **R2-quiet ≥T ms pre-event** + no Cross-snap edge in the same window (weak proxy) — or operator-labeled defensive drives in v0. |
| **Dual stimulus** | Require **both** `playclock_reset` (OCR) **and** optical motion onset (center/banner luminance jump) within Δt; if only one fires → NULL (honest), not a latency. |
| **OCR lag gate** | If OCR pipeline latency p95 > X ms (calibrate on desk), mark samples `stimulus_uncertain` and exclude from band claims. |
| **Population band, not identity** | 80–280 ms is L6b population physics — presence evidence, not who. Same as PoEP: no cross-session identity claim. |
| **Script signature = low CV + sub-floor rate** | Flag shape: (fraction of snaps < human_floor) AND (CV of latency < human_floor_cv) over N≥20. Single fast snap never flags. |
| **Anticipation window** | Inputs in [−150, 0] ms relative to stimulus are **ANTICIPATION**, not REACTION. Count separately; never call them bot. |
| **No haptic requirement** | Strength of S3 is game-as-stimulus; do not smuggle L6b fire into the metric. Campaign haptics remain orthogonal (S1). |
| **Fail-open** | Missing OCR, MENU context, CONTESTED host, or dual-stimulus fail → no claim. |

**Bottom line:** S3 is the right novel seed and the easiest to **over-claim**. Ship as INDICATIVE distribution logger first; adversary-test with deliberate hard-count sessions before any severity language.
