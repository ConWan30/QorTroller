### 1. SETTLE threshold = circular / wrong

**Yes. Gate threshold ≠ science threshold.**

- Gate: `TAIL_SLOPE_MIN = -0.030` in `poep_waveform_shape.py` splits **synth human** (tail ~flat, banked mean ≈ 0.0003) from **synth triangle** (still descending). Docstring already calls settle-to-plateau an **EMPIRICAL ASSUMPTION** for rung 2.
- Analyzer: `SETTLE_TAIL_SLOPE = TAIL_SLOPE_MIN` → `mean_tail >= -0.030` → `real_reflexes_settle_to_plateau` + SETTLES/RETURNS verdict.

That boolean does **not** answer “do real reflexes settle?” It answers “does mean `tail_slope` clear the constant that was chosen so synth human clears the gate?” A slow return-to-baseline with mean = −0.02 would still get **SETTLES-TO-PLATEAU**. Circular.

**Smallest fix (remove circularity):**
1. Drop `SETTLE_TAIL_SLOPE = TAIL_SLOPE_MIN` as the science decider.
2. Always emit distribution: `mean / median / min / max / std` (and ideally p10/p90) of `tail_slope`.
3. Optional non-gate physical readouts: e.g. `mean(last_quarter) / amp` (still elevated vs back near 0), or fraction with `|tail_slope| < ε` in **normalized units** with ε chosen for “flat within noise,” not copied from the gate.
4. Keep `real_data_shape_gate_pass_rate` / per-reflex `passes_human_shape_gate` as a **separate FRR-proxy that intentionally uses gate constants**.

### 2. Window / latency / tail validity

**Brief understates post length; alignment issue is real.**

Defaults: hold 200 + capture 400 → **~600 ms post**, not ~400. At 8 ms → **~75 samples**, not ~50. Tail = last 25% ≈ **19 samples / ~152 ms**.

| latency | ~peak sample (n≈75) | after-peak | peak in “tail”? |
|--------|---------------------|------------|-----------------|
| 80–200 ms | 16–31 | plenty | no |
| 280–300 ms | 41–43 | ~32 | no (with n=75) |
| same, **n=50 only** | 41–43 | ~7–9 | **yes — broken** |

- P-WAVE-0 is **onset-aligned** N=40 (~320 ms pure reflex). Live curves are **challenge-aligned**; first 19–35 samples are pre-onset quiet. Features are not onset-sliced.
- For mid-band latency (~150–200 ms) and default 600 ms post, last-quarter can be post-peak enough for a **flat vs descending** read.
- For slow end-of-band latency (~280–300 ms) or if someone sets capture short / hold 0, “tail” is still rise/early relaxation → **analyzer cannot answer settle-vs-baseline**.
- Stimulus is **hold then clear** (~200 ms), not an impulse; “plateau” can be residual grip / force lifecycle, not pure free response.

**So:** default window is *probably* enough for typical 150–200 ms reflexes; it is **not** guaranteed for the full reaction band, and features were designed for onset-aligned synth. Window is a second-order trust problem after #1, not a free pass.

**Smallest capture-side harden (optional, not the #1 fix):** onset-align (trim to peak − k) before shape features, and/or lengthen post to ≥800–1000 ms so slow reflexes have a true settled tail.
