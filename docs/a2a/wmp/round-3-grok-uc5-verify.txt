### 1. Consent binding vs host-forged consent

**What it does:** `row_commit` binds `consent_bits | cross | gec | field | value` into one SHA-256. Flip any bit → new leaf → different merkle root.

**What it does *not* do:** This module never checks that `gamer_export_commitment` was gamer-signed or that it was derived from a package that already encodes those consent bits. Host who **invents both** `consent_bits=1` and a fresh `gec` still produces a self-consistent triple.

**Verdict on the claim:** That residual is exactly DEPIN-1 **format-not-truth**, and the **ceiling block states it honestly** (code `ceiling` string + doc §Honest ceiling).  
The rail wording *“cannot forge consent=1 without the published gec”* is only true if the buyer independently holds/verifies a prior gamer-attested export under that `gec`. Alone, the applet is **format binding**, not a consent oracle. **Not over-claim if ceiling is load-bearing; mild wording tightness only.**
