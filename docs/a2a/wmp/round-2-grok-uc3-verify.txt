### 2. Footguns

**(a) Pre-check vs circuit — no hide, C3/C4 still load-bearing**

- Pre-check: enum / claim match / expiry → clean exits 4/5/6.
- Prover **always recomputes** commitment + nullifier from privates; it does not accept a caller-supplied mismatched commitment.
- Circuit still enforces C3/C4: you cannot fullProve a forged public commitment without the preimage.
- Pre-check does **not** replace C3/C4; it only short-circuits obvious fails.

**(b) Nullifier — deterministic is correct; reuse is consumer-side**

- `Poseidon(DID, nonce)` = one nullifier per credential: **correct** for spend-once.
- Same credential → same nullifier every prove: **by design** (anti-replay set).
- Prover should **not** invent “already used” — that is on-chain/app nullifier set.
- Privacy: uses of the **same** credential are linkable via nullifier until spent; DID stays hidden if only the proof is shown.

### 3. Self-chosen credential — **product/issuance gap, not prover bug**

Yes: anyone can invent `(DID, cat, nonce, issued, expires)`, compute commitment, and prove category C. Circuit only proves preimage of a **public** commitment.

**Trust must anchor outside the proof:**

1. Curator-published membership of `credentialCommitment` (circuit docs option b), **and**
2. Nullifier not spent, **and**
3. `currentTimestamp` set by verifier (not blindly trusted from buyer).

**Honesty vs live registry:** `VAPIBuyerRegistry` stores `buyerDID` + `evidenceHash` (sha256 docs) + category/times — **not** Poseidon `credentialCommitment`. So option-(b) membership is **not** wired end-to-end today. That is an **issuance/composability gate**, not a UC-3 prover defect. Document it; do not pretend the prover alone is marketplace authorization.
